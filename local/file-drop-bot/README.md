# file-drop-bot

Telegram-бот «файл → одноразовые utm-ссылки → 10 строк». Владелец кидает боту
`.txt` со строками, бот отдаёт ссылки; **каждая ссылка срабатывает один раз** —
первый перешедший забирает свои **10 строк** (настраивается), и ссылка сгорает.
Раздаёшь по одной ссылке на человека.

## Как работает

- Партия (`drops`) — один загруженный файл. Строки лежат в `lines`, пустые
  выкинуты, дубликаты по умолчанию тоже (`DEDUPE_LINES`).
- На партию можно навесить сколько угодно utm-ссылок (`links`): `/link 3 tiktok`
  → `https://t.me/<bot>?start=tiktok`. Статистика считается по каждой ссылке
  отдельно, а строки берутся из общего пула партии.
- Переход по ссылке → `issues`: посетителю выдаются 10 строк, и эти строки
  **физически вырезаются из пула** (`lines`), а их копия кладётся в `issued`.
  Одна и та же строка не достанется двоим, «файл» реально худеет: 100 строк по
  10 = ровно 10 человек, дальше выдавать нечего.
- **Каждая ссылка — одна активация в целом** (уникальность по `issues.code`).
  Первый перешедший забирает 10 строк, ссылка сгорает. Он же при повторном заходе
  видит свой набор из `issued`; чужой видит «ссылка уже активирована». Один
  человек может активировать несколько разных свежих ссылок — ограничение на
  ссылке, не на человеке.
- Если свободных строк осталось меньше 10, выдаётся остаток; когда пул пуст,
  посетитель видит «всё разобрали».
- Выдача приходит текстом в `<pre>`, а если длинная (> 3500 символов) — файлом.
- Владельцу летит уведомление о каждой выдаче с остатком (`NOTIFY_OWNER=0`
  отключает).

## Команды владельца

| Команда | Что делает |
|---|---|
| файл `.txt` | новая партия + первая одноразовая ссылка |
| `/add [id]` + файл | дописать строки в партию |
| `/drops` | партии: осталось / всего |
| `/gen [id] N` | начеканить N одноразовых ссылок (по одной на человека) |
| `/links [id]` | все ссылки партии: 🟢 свежая / 🔒 использована / 🔴 выключена |
| `/link [id] [utm]` | одна новая ссылка, можно со своим кодом |
| `/who [id]` | `.tsv`-отчёт: кто, по какой ссылке, когда, сколько строк |
| `/off id`, `/on id` | закрыть / открыть выдачу партии |
| `/offlink код`, `/onlink код` | то же для одной ссылки |
| `/drop_delete id` | удалить партию со ссылками и статистикой |
| `/stats` | общая сводка |

Без `id` команды работают с последней загруженной партией.

## Настройка и запуск

1. `@BotFather` → новый бот → токен в `.env` (`cp .env.example .env`),
   `OWNER_ID` — свой Telegram id.
2. `pip install -r requirements.txt`
3. `python run.py` — проверить руками; `pythonw run.py` — без окна.
4. Держать живым на этой машине (тот же паттерн, что `KiroBot`/`BotFarm`,
   но свои задачи — существующие не трогаются):
   - `pwsh -File install_task.ps1` → задача `FileDropBot` (автозапуск при
     логоне, авторестарт каждую минуту при падении);
   - `pwsh -File install_watchdog.ps1` → задача `FileDropBotWatchdog` (каждые
     2 минуты поднимает процесс, если он умер).

## Файлы

```
run.py                 точка входа

app/storage.py         SQLite: drops / lines (пул) / issued / links / issues; выдача вырезает строки из пула
app/handlers.py        aiogram-роутер: deeplink для гостей, команды для владельца
tests/test_storage.py  сценарий выдачи (python tests/test_storage.py)
data/drops.sqlite3     база (в git не попадает)
file-drop-bot.log      лог с ротацией
```

## Заметки

- Ключ уникальности выдачи — `issues.code` (одна активация на ссылку). Хочешь
  другой лимит (на человека / на партию) — поменяй UNIQUE-индекс в `storage.py`
  и правило поиска в `Storage.issue`.
- `Storage.open()` ставит `busy_timeout` и делает схемные правки только когда
  они реально нужны — иначе два одновременных старта (основная задача + watchdog)
  дерутся за write-lock на `issues` и один процесс залипает.
- Выдача сериализована через `asyncio.Lock` в `Storage.issue`, так что двум
  одновременным переходам одинаковые строки не уйдут.
- Строки в start-параметре Telegram ограничены `[A-Za-z0-9_-]`, до 64 символов —
  свои utm-коды проверяются этим же правилом.
