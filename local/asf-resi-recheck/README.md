# asf-resi-recheck — «проверить и заменить нерабочие» резидентские прокси

Доработка резидентских прокси в **botshop `/api/v1`** и **ASF shop / Nexo Shop**
(оба на srv2): выдавать клиенту только рабочие прокси и авто-заменять «сдохшие».

## Что изменилось

### botshop `/opt/botshop` (`vproxy_service.py`, `miniapp.py`)

- `_check_proxy_line` — цель CONNECT-пробы вынесена в `MASKIFY_PROBE_HOST`/
  `MASKIFY_PROBE_PORT` (по умолчанию `www.google.com:443`, надёжнее чем instagram);
  добавлен `_canonicalize_proxy_line` — приводит любой из 4 форматов строки
  (`host:port:login:password` и т.д.) к `http://login:password@host:port` перед
  пробой, иначе `urlsplit` падал на не-URL форматах.
- `_collect_working_residential_lines` — генерит gateway-сессии и, если включена
  валидация, пробит их и **до-генерит замену «мёртвым»** сессиям (до
  `MASKIFY_DELIVERY_ROUNDS`=4 раундов), пока не наберёт нужное число рабочих.
  Порог `MASKIFY_DELIVERY_MIN_RATIO`=0.5: если после всех раундов рабочих меньше
  половины — ошибка, иначе отдаём что есть.
- Валидация по умолчанию **только для API-пути** (`generate_api_residential_client_proxies`
  → ASF) и нового refill. Родные пути botshop (`generate_maskify_proxies`,
  выдача при покупке) — без изменений (`validate_default=False`), чтобы не
  трогать денежный флоу. Глоб. выключатель `MASKIFY_DELIVERY_VALIDATE=0`.
  Пропуск валидации выше `MASKIFY_DELIVERY_VALIDATE_MAX`=50 строк.
- `refill_api_residential_client_proxies(api_user_id, client_id, lines, settings)`
  — пере-проверяет список, для каждой дохлой строки берёт свежую рабочую
  сессию **на том же субъюзере** (пул/биллинг не трогается, меняется только
  session-селектор). Порядок строк сохраняется.
- Новый роут `POST /api/v1/proxy/residential/clients/{id}/proxies/refill`
  (`handle_public_api_residential_refill`) → `{data, checked, alive, dead, replaced}`.
  В OpenAPI добавлен.

### ASF `/opt/asf/app` (`clients.py`, `db.py`, `handlers_user.py`, `keyboards.py`)

- `SousClient.residential_refill(client_id, lines, settings)` — вызов нового роута.
- Таблица `residential_deliveries(user_id, lines_json, updated_at)` +
  `save_residential_delivery` / `get_residential_delivery` — последняя выданная
  клиенту пачка (до relay-подмены хоста), чтобы re-check работал по реальным
  строкам.
- `rm_get` теперь сохраняет выданное и пишет в подпись «проверены».
- Новый хендлер `rm:recheck` + кнопка «♻️ Проверить и заменить нерабочие» в
  `residential_manage_menu`: берёт сохранённый список → `residential_refill` →
  отдаёт обновлённый файл с подписью «Проверено N · заменено нерабочих: K».
  Если сохранённого списка нет — фолбэк на обычную выдачу.

### ASF автопроверка (всегда включена) — `residential_autocheck.py`

Фоновый цикл в `main.py` (`residential_autocheck_loop`), стартует через 90 с
после запуска, дальше каждые `RESIDENTIAL_AUTOCHECK_MIN` минут (по умолчанию 30,
`0` = выкл). Каждый проход:

- берёт всех клиентов из `residential_deliveries`;
- пропускает тех, у кого на суб-агенте `remaining_gb ≈ 0`;
- гоняет их список (до `RESIDENTIAL_AUTOCHECK_MAX_LINES` = 50 строк) через
  `residential_refill` — дохлые меняются на рабочие на том же субъюзере;
- сохраняет обновлённый список (кнопка «Получить прокси» и уже скачанный файл
  остаются актуальными);
- если что-то заменено — **один DM клиенту** с новым файлом, не чаще
  `RESIDENTIAL_AUTOCHECK_NOTICE_HOURS` = 6 ч.

Таблица `residential_deliveries` получила колонки `last_check_at`,
`last_notice_at` (миграция ALTER, идемпотентная). Пауза 2 с между клиентами,
любая ошибка по одному клиенту не роняет проход.

### Багфикс ротации (2026-09-09, по жалобе техподдержки)

`_build_residential_line` **всегда** добавлял `-s-<session_id>` к логину — и в
режиме «ротация каждый запрос» тоже. На живом шлюзе `-s-<id>` = **фиксированный
IP** (проверено: 2 запроса с одним `-s-` → один IP; без `-s-` → каждый запрос
новый IP). Итог: клиент ставил «по запросу», а получал один прокси на все
запросы.

Фикс: `-s-` (и `-ttl-`) добавляются **только в sticky**. Ротация теперь —
один «голый» эндпоинт `user-cc-XX:pass@host:port`, повторённый до нужного
количества строк (каждое соединение через него = новый IP; для многопоточных
клиентов N одинаковых строк = N параллельных разных IP). Sticky — как было: N
разных `-s-<id>[-ttl-<n>]`, каждая строка = свой постоянный IP.
`_collect_working_residential_lines` в rotating-режиме пробит эндпоинт один раз
(с ретраями по раундам) и размножает. Старые кривые строки у клиентов
автопроверка вылечит сама (протухший `-s-` → dead → замена на правильный
ротирующий эндпоинт + DM).

Проверено в проде: rotating 3 запроса → `73.7.121.43 / 76.95.122.61 /
24.176.128.115`; sticky одна строка ×2 → один IP, разные строки → разные IP.

### Фильтр качества: гео + Instagram + пинг (2026-09-09)

При валидации (путь ASF + refill + автопроверка) теперь для каждого кандидата
делается «глубокая» проверка `_probe_residential`:

1. **Гео + пинг** — GET через прокси на `ip-api.com` (`MASKIFY_GEO_API`): меряет
   RTT и берёт `countryCode`. Не совпал с запрошенной страной → отброс
   (`MASKIFY_VERIFY_GEO=1`).
2. **Instagram** — GET через прокси на `https://www.instagram.com/`
   (`MASKIFY_IG_PROBE_URL`, браузерный UA, без редиректов). `200/30x` = ок;
   `403/429` (бан/флаг IP) → отброс.
3. **Пинг** — RTT из шага 1 должен быть ≤ `MASKIFY_MAX_PING_MS` (3000).

- **Sticky**: генерит ×4 кандидатов, пробит все параллельно, оставляет
  прошедшие, **сортирует по пингу** и отдаёт самые быстрые N.
- **Rotating**: сэмплит эндпоинт `MASKIFY_ROTATING_SAMPLES` (4) раз (каждый
  запрос = другой IP); если прошло меньше `MASKIFY_ROTATING_MIN_PASS` (0.5) —
  ошибка «шлюз отдаёт мало рабочих IP».
- **refill / автопроверка**: строка считается «плохой» не только если мертва, а
  и если не грузит Instagram / не та страна / медленная — и заменяется.

Выключатель: `MASKIFY_QUALITY_FILTER=0` → откат на простой CONNECT-чек.
`MASKIFY_DELIVERY_VALIDATE_MAX` снижен до 20 (проба тяжелее). `SousClient`
получил параметр `timeout`; вызовы выдачи/refill идут с `timeout=150`.

Проверено в проде: rotating US — `checked=4 passed=4 avg_ping_ms=291`; sticky US
×3 — `checked=12` кандидатов, отдал 3 разных быстрых, все проходят Instagram+гео.
Один из 4 сэмплов rotating честно отсеялся по `ig=False` (IP забанен в IG).

### Разные строки + тихая автозамена (2026-09-09, по жалобе)

Клиент в режиме «ротация» получал 10 **одинаковых** строк, а автопроверка каждый
цикл слала DM «10 нерабочих заменены».

- `_build_residential_line`: теперь **каждая строка — свой `-s-<id>`**, т.е.
  список = N разных IP, а не N копий. Ротация добавляет `-ttl-<n>`
  (`MASKIFY_ROTATING_TTL`, 300 с) — каждый IP сам меняется по этому интервалу;
  sticky — `-ttl-` только если клиент задал. Спец-ветка «один эндпоинт ×N»
  удалена; оба режима идут через общую генерацию N сессий + фильтр качества.
- `refill` дедупит одинаковые входные строки (пробит уникальные один раз) —
  чинит старые «10 копий» списки в N разных.
- **Автопроверка теперь тихая**: `RESIDENTIAL_AUTOCHECK_NOTIFY` (по умолчанию
  `0`) — просто молча обновляет сохранённый список «в пуле», без DM. Клиент
  в любой момент жмёт «Получить прокси» / открывает меню и получает актуальный
  рабочий список. `=1` вернёт уведомления (throttled 6 ч), с нейтральным текстом.

Проверено в проде: rotating US ×5 → 5 разных строк, 5 разных exit-IP
(`69.138.226.178 / 47.184.189.96 / 68.4.156.218 / 73.147.65.118 / 73.201.118.64`),
все прошли Instagram + гео + пинг (`checked=20 → delivered 5`).

### Нагрузка / оптимизация (2026-09-09)

srv2 = 1 vCPU / 2 ГБ, load уже ~1.0 (релей + реальный трафик клиентов). Чтобы
фичи не давили:

- **CPU/RAM**: всё async-I/O (ждём сеть), парсинг ответов копеечный. Свип
  автопроверки трогает теперь **~1 запрос на клиента** (сэмпл 3 строк), идёт
  ~1–2 с раз в час. Тяжёлая проба (при нажатии «Получить прокси») — ~20–40
  запросов, 15–30 с, но по клику и редко, и не блокирует бота.
- **GB клиента** (пробы идут через его субъюзер): IG-проба переведена на
  `favicon.ico` (~4 КБ вместо ~100 КБ страницы, ×25). Автопроверка: сэмпл 3
  строк раз в час, полный refill только если сэмпл нашёл проблему → в покое
  ~1 МБ/сутки на всех.
- **Релей srv2**: пробы ходят напрямую на шлюз maskify, не через
  `botshop-proxy-relay`, так что его 18080 не грузят.
- Интервал автопроверки поднят 30 → **60 мин** (`RESIDENTIAL_AUTOCHECK_MIN`).
- Рубильники если что: `MASKIFY_QUALITY_FILTER=0`, `RESIDENTIAL_AUTOCHECK_MIN=0`,
  `MASKIFY_DELIVERY_VALIDATE=0`, `RESIDENTIAL_AUTOCHECK_SAMPLE`.

## Деплой (сделан 2026-09-09)

`deploy_botshop.sh <STAMP>` и `deploy_asf.sh <STAMP>` — бэкап → компиляция →
swap → restart → health-check (+ проверка роута/таблицы) → авто-откат.
Бэкапы: `/opt/botshop/backups/resi-recheck-*`, `/opt/asf/backups/resi-recheck-*`.

Оба сервиса подняты чисто (health 200, 0 tracebacks). E2E проверено против
живого maskify: `generate` отдал 3 рабочих, `refill` с 3 живыми + 1 мёртвой →
`checked=4 alive=3 dead=1 replaced=1`, порядок сохранён.
