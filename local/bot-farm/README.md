# bot-farm

Главный Telegram-бот, который управляет парком других ботов. Загружаешь ему
`.txt`-файл со списком токенов — для каждого токена бот поднимает отдельного
Telegram-бота, который копит аудиторию (запоминает всех, кто написал ему
`/start` или что угодно) и отвечает заданным текстом на любое сообщение.

## Как это работает

- Один процесс, один `aiosqlite`-файл (`data/bots.sqlite3`).
- Главный бот (`app/main_handlers.py`) слушает только владельца (`OWNER_ID`) и
  принимает `.txt`-файлы + команды администрирования.
- `app/manager.py` — держит по одному `aiogram.Bot` + `Dispatcher` на каждый
  добавленный токен и опрашивает их все параллельно (asyncio-таски в одном
  процессе, отдельные процессы не нужны).
- `app/child_handlers.py` — единый хэндлер для всех дочерних ботов: на любое
  личное сообщение запоминает пользователя в `audience` и отвечает текстом,
  заданным для этого бота (или общим текстом по умолчанию).

## Формат файла с токенами

Одна строка — один бот:

```
123456:AAExampleToken1
789012:AAExampleToken2 | Привет! Мы скоро откроемся, следите за новостями.
345678:AAExampleToken3|Спасибо, что подписался
```

Без `|текст` бот использует `DEFAULT_REPLY_TEXT` из `.env`, пока владелец не
задаст текст через `/settext`.

## Команды главного бота

- `/start`, `/help` — инструкция
- `.txt`-файл — добавить/перезапустить ботов из списка токенов
- `/list` — список ботов: статус (🟢 запущен / 🔴 остановлен), размер
  аудитории, текст ответа
- `/settext @username текст` — текст ответа для одного бота
- `/setall текст` — текст ответа для всех сразу
- `/stats` — сводная статистика
- `/remove @username` — остановить и удалить бота (аудитория стирается)
- `/broadcast @username текст` — разослать текст всей накопленной аудитории
  этого бота (с паузой 50мс между отправками, чтобы не словить flood-limit)

## Запуск локально

```bash
cd project/bot-farm
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt   # Windows
cp .env.example .env    # впиши BOT_TOKEN и OWNER_ID
.venv/Scripts/python -m app.main
```

## Конфиг (`.env`)

| Переменная | Смысл |
|---|---|
| `BOT_TOKEN` | токен главного бота-управления |
| `OWNER_ID` | твой Telegram user id — только он может слать команды |
| `DEFAULT_REPLY_TEXT` | текст ответа для ботов, которым не задан свой |

## Деплой на сервер (systemd)

```bash
scp -r project/bot-farm root@SRV:/opt/bot-farm
ssh root@SRV 'cd /opt/bot-farm && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt'
# положить .env в /opt/bot-farm/.env
ssh root@SRV 'cp /opt/bot-farm/deploy/bot-farm.service /etc/systemd/system/ && systemctl daemon-reload && systemctl enable --now bot-farm'
```

Логи: `journalctl -u bot-farm -f`

## Ограничения / что учесть

- У каждого дочернего токена не должно быть уже запущенного где-то ещё
  polling-а (Telegram отдаёт `409 Conflict`, если один токен опрашивают
  одновременно из двух мест).
- Все боты опрашиваются в одном процессе одним event loop'ом — это не
  бутылочное горлышко для десятков ботов, но для очень большого парка
  (сотни) лучше следить за памятью/CPU процесса.
- `/broadcast` не проверяет 429 от Telegram отдельно — при большой аудитории
  стоит поднять паузу между отправками.
