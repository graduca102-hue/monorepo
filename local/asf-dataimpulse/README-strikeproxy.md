# StrikeProxy — второй поставщик прокси в Nexo Shop

Добавлен 2026-09-24 в тот же раздел «🌐 Proxy» бота Nexo Shop (`/opt/asf`,
systemd `asf.service` на srv2). DataImpulse (см. `README.md`) остался в коде, но
без логина не настроен, поэтому его пулы в меню **не показываются** — сейчас
прокси продаются только через StrikeProxy.

## Аккаунт и API

- Дашборд/док: <https://strikeproxy.net/strike/reseller>, <https://strikeproxy.net/strike/docs>
- База: `https://strikeproxy.net/api`, авторизация `Authorization: Bearer sp_live_…`
- Ключ лежит в зашифрованных настройках шопа под `sp_api_key`
  (записывается `set_di_secret.py sp_api_key <value>`, в чат не печатается)
- Аккаунт `lineigo`, заявка реселлера одобрена (`business_name = Nexo Shop`),
  баланс реселлера на момент внедрения — $100

**Cloudflare.** `strikeproxy.net` за Cloudflare, и без браузерного
`User-Agent` API отвечает JS-челленджем вместо JSON. Поэтому
`app/strikeproxy.py` всегда посылает UA (`SP_USER_AGENT`) — убирать нельзя.

## Закупочные цены (реальные, из API)

`GET /api/reseller/catalog` отдаёт прайс именно этого аккаунта, так что
себестоимость не вводится руками и не выдумывается:

| Пул | `plan_key` | Закупка | Продажа при наценке 100 % |
|---|---|---|---|
| 🏠 Резидентские | `residential` | 0.50 $/GB | 1.00 $/GB |
| 📱 Мобильные | `mobile` | 0.80 $/GB | 1.60 $/GB |
| 🖥 Датацентр | `datacenter` | 0.30 $/GB | 0.60 $/GB |

Цены подтягиваются сами: при открытии раздела (не чаще раза в 6 ч), кнопкой
**🛠 Админка → 🔑 Ключи → 🧪 Проверить StrikeProxy** и после каждой покупки — по
фактически списанной сумме (`cost / GB` из ответа заказа). Пишутся в настройки
`sp_cost_<plan>`. Пока цены нет, пул показывает «цена уточняется» и покупка
блокируется до списания — правило «не продавать по выдуманной цифре» сохранено.

Тарифы `unlimited` / `unlim_datacenter` (оплата за время, не за GB) в бота **не
заведены** — нужен отдельный сценарий покупки по часам.

## Модель

У поставщика нет суб-аккаунтов: покупка создаёт **сервис** со своим
логином/паролем и запасом GB, добавка трафика идёт в тот же сервис.

- первая покупка пула → `POST /api/reseller/order {plan, quantity}` (списание с
  баланса реселлера, креды приходят сразу);
- последующие пополнения → `POST /api/proxy/add-bandwidth {proxy_username, add_gb}`;
- расход → `GET /api/reseller/services` (`used_gb`), кэш 30 с на все сервисы;
- смена пароля → `POST /api/proxy/update-password` (бесплатно, все ранее выданные
  прокси перестают работать).

Таблицы в `data/shop.db`:

- `sp_services(user_id, plan, service_id, proxy_username, proxy_password, paid_gb, provisioned_gb)`
- `sp_settings(user_id, plan, settings_json)` — гео, режим, TTL, формат, количество

`paid_gb` — сколько покупатель реально оплатил (дробное), `provisioned_gb` —
сколько целых GB залито поставщику. API берёт только целые GB, поэтому
заливается `max(1, ceil(paid_gb))`: минимума для покупателя нет (можно взять
0.05 GB), разницу магазин дарит — как и на DataImpulse.

## Выдача прокси

`POST /api/reseller/proxy/generate` (до 10 000 строк за раз): гео, протокол,
формат, тип сессии. Особенности:

- **режим «Ротация» реализован как sticky с TTL 1 минута** (`SP_ROTATING_MINUTES`).
  Родной `session_type=rotating` у поставщика возвращает N **одинаковых** строк —
  это нарушает правило владельца «в списке не должно быть повторов», поэтому не
  используется. В sticky каждая строка получает свой `session-strike_xxxxxxxx`;
- «Фикс. IP» — `session_minutes` из меню (5 мин … 2 ч, лимит API 120 мин);
- хост поставщика (`beta.strikeproxy.net:8080`, CNAME на `global.nullproxies.com`)
  подменяется на свой релей **`31.77.145.160:18082`** — systemd
  `sp-proxy-relay.socket` + `.service` на srv2 (`systemd-socket-proxyd`), тот же
  приём, что 18080 (maskify) и 18081 (DataImpulse). Переопределяется
  `SP_RELAY_ENDPOINT`; пусто — отдавать гейт напрямую.

## Наценка прокси — отдельный экран

**🛠 Админка → ⚙️ Курсы и наценка → 💹 Наценка Proxy**: общая наценка Proxy плюс
своя наценка на каждый пул (`proxy_markup_<код секции>`, например
`proxy_markup_sp_mobile`). Своя перекрывает общую, кнопка «♻️ Сбросить наценку»
возвращает к общей. На экране сразу видно «закупка → цена продажи» по каждому
пулу, так что цену прокси можно менять, не трогая товары, курс и минимальную
цену.

Коды секций у StrikeProxy — `sp_residential`, `sp_mobile`, `sp_datacenter`
(префикс, чтобы не пересекаться с пулами DataImpulse). Они же используются в
**🛒 Товары в категориях → 🌐 Proxy** для переименования и скрытия пулов.

## Переменные окружения (необязательные)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SP_API_BASE` | `https://strikeproxy.net/api` | база API |
| `SP_USER_AGENT` | Chrome UA | обязателен для прохода Cloudflare |
| `SP_GATEWAY_HOST` / `SP_GATEWAY_PORT` | `beta.strikeproxy.net` / `8080` | гейт поставщика |
| `SP_RELAY_ENDPOINT` | `31.77.145.160:18082` | что видит покупатель |
| `SP_ROTATING_MINUTES` | `1` | TTL сессии в режиме ротации, мин |

## Деплой и проверки

```
python project/_ops/srv_put_b64.py srv2 project/asf-dataimpulse/app/<file> /opt/asf/_stage_sp/<file>
python project/_ops/srv_run.py srv2 "bash /opt/asf/deploy_sp.sh"
```

`deploy_sp.sh` — бэкап в `/opt/asf/backups/<stamp>/`, байт-компиляция staging,
установка, перезапуск `asf`, проверка `is-active` + `/health` = 200 + отсутствие
свежего `Traceback`, иначе авто-откат (включая удаление нового
`strikeproxy.py`).

Скрипты рядом:

- `test_sp.py` — смоук: новые таблицы, наценка по секциям, подмена хоста в
  строках, и read-only вызовы API (профиль, баланс, каталог, сервисы, гео).
  Ничего не покупает. Запуск: `SP_KEY=… ./.venv/bin/python /opt/asf/_stage_sp/test_sp.py`
- `sync_sp_costs.py` — подтянуть прайс реселлера в настройки и показать цены продажи
- `check_proxy_menu.py` — показать, какие пулы и по какой цене увидит покупатель

## Сбои поставщика и деньги

24.09 покупатель четыре раза подряд получил ошибку на покупке 10 GB: origin
StrikeProxy отдавал Cloudflare **502** на `POST /reseller/order`. Исправлено:

- **5xx на записи больше не считается «ничего не произошло».** Раньше любая
  ошибка означала откат и возврат денег покупателю, хотя заказ мог уйти
  поставщику — это оплаченный, но потерянный трафик.
- **Перед возвратом бот проверяет поставщика.** После неудачной покупки
  запрашивается `GET /reseller/services`: если появился сервис нужного пула,
  которого нет ни у одного покупателя, он «усыновляется» (`_sp_orphan_service`
  / `_sp_adopt_service`) — заказ считается успешным, второй раз не платим. Для
  докупки сравнивается `purchased_gb` у поставщика с тем, что бот уже залил.
- **Если поставщик недоступен и проверить нечем** — заказ уходит в статус
  `review` (деньги зарезервированы, не возвращаются вслепую), а админам падает
  уведомление в Telegram.
- Один автоматический **повтор** делается только после того, как проверка
  показала, что у поставщика ничего не появилось.
- Cloudflare-текст ошибки больше не показывается покупателю (он называл стек
  поставщика) — вместо него «Сервис временно недоступен, попробуйте позже».
- Админам приходит уведомление и на чистый отказ (с троттлингом 15 мин на пул),
  чтобы о простое поставщика узнавать не от покупателя.

Сценарии покрыты `test_sp_recovery.py` (поставщик замокан, деньги не тратятся):
заказ потерян но прошёл / потерян и не прошёл / прошёл с повтора / поставщик
недоступен / докупка потерялась но залилась / докупка не прошла.

## Две разные закупочные цены — и почему это важно

У поставщика **новый заказ и докупка трафика стоят по-разному**:

| Операция | Что платим за GB (mobile) |
|---|---|
| `POST /reseller/order` — новый аккаунт | 0.80 $ (как в каталоге) |
| `POST /proxy/add-bandwidth` — докупка в существующий | **1.40 $** |

Проверено дважды: докупка 10 GB списала ровно 14.00 $, докупка 1 GB — 1.40 $
(в ответе видно и их собственную себестоимость, `nettify_cost: 0.59`).

Этим же объясняется «пропавшая шестёрка» в балансе реселлера, о которой
сообщалось раньше: 0.80 (заказ 1 GB) + 14.00 (докупка 10 GB) + 5.60 (заказ
7 GB) = 20.40, 100 − 20.40 = 79.60 — сходится до цента. **Неудачные 502-заказы
не списали ничего.**

Опасность в том, что второй и все последующие заказы покупателя — это всегда
докупка. При цене продажи, посчитанной от каталожных 0.80, магазин отдавал бы
повторные покупки почти в ноль. Поэтому:

- ставки хранятся раздельно: `sp_cost_<plan>` (новый заказ) и
  `sp_cost_<plan>_topup` (докупка), обе видны и редактируются в
  **⚙️ Курсы и наценка**;
- цена покупателю считается от **большей** из двух;
- калибровка по факту списания пишет в «свой» ключ и сравнивает показание
  только с показанием того же типа (порог `SP_CALIBRATE_MAX_DEVIATION` = 25 %
  отсекает одиночные выбросы, но больше не глушит настоящую разницу между
  заказом и докупкой).

Итог для mobile: закупка 1.40 → в витрине **2.80 $/GB** при наценке 100 %
(было 1.60 при реальной марже 0.20).

## Что осталось

- Сквозная покупка проверена живыми деньгами 24.09: три успешных заказа
  (1 + 10 GB у владельца, 7 GB у покупателя), выдача и работа прокси через релей
  подтверждены.
- **Пул «Mobile» на самом деле не мобильный.** 30 проверенных выходов — только
  2 настоящих оператора (Celcom MY, T-Mobile PL), остальное проводные ISP
  (Ростелеком, Comcast, BT, Türk Telekom…). По RU — 5 из 5 проводные. Продавать
  его как мобильный нельзя; настоящая мобилка у других поставщиков стоит
  3–5 $/GB (Proxyma: 5 $/GB за 1 GB, 3 $/GB за 50 GB).
- **Новые mobile-аккаунты поставщик создать не может.** `POST /reseller/order`
  для `mobile` стабильно отвечает 502 (проверки 18:16–18:59). При этом проверка
  баланса внутри того же эндпоинта отрабатывает за 0.4 с (заведомо неподъёмный
  заказ отбивается `insufficient_funds`), `order` для `datacenter` проходит, а
  `add-bandwidth` для существующего mobile-аккаунта проходит. То есть сломана
  именно выдача новых мобильных аккаунтов — вопрос к поддержке поставщика.
