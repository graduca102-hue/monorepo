# asf-dataimpulse — прокси Nexo Shop на DataImpulse

Замена прокси-раздела «ASF shop» / **Nexo Shop** (`/opt/asf` на srv2, systemd
`asf.service`) с SOUS API на **DataImpulse reseller API**.
Раздел «Товары» (Instagram / YouTube через SOUS) не тронут.

## Что убрано

Из бота полностью удалены прокси, приходившие из SOUS API:

- «Выделенные прокси» (`px:dedicated`, `pxc:`, `pxp:`) — каталог стран/протоколов;
- витрина прокси-сервисов 9Proxy / PIA / 922 / ABC / LokiProxy / Proxy001 /
  711 / CliProxy (`pxs:`, `pxg:`, `pxsb:`);
- резидентские прокси через maskify-пул SOUS (`rm:*`), общий пул + entitlements,
  релей `31.77.145.160:18080`, фоновый `residential_autocheck.py`;
- из `app/clients.py` вырезаны все прокси-методы SOUS, кроме
  `proxy_service_order_status` — он нужен для проверки старых заказов
  `kind='proxy_service'`, оставшихся в базе.

Старые файлы с SOUS-логикой лежат в `_prev_sous/` — только как справка.

## Что появилось

`app/dataimpulse.py` — клиент reseller API (`https://api.dataimpulse.com/reseller`)
и сборщик прокси-строк. Авторизация: `POST /user/token/get` с логином (e-mail из
раздела **API Management** в дашборде) и паролем → JWT на 24 ч; токен кэшируется
в памяти на 20 ч и обновляется сам при 401.

Четыре пула — `residential`, `residential_premium`, `mobile`, `datacenter`.
В меню «🌐 Proxy» они выводятся отдельными кнопками с ценой за GB.

### Модель

У каждого покупателя — **свой суб-аккаунт DataImpulse на каждый пул**
(`POST /sub-user/create`, label `asf<telegram_id> <pool>`, sticky_range
10000–20000). Никакого общего пула и reconcile, как было с maskify: трафик
покупателя лежит на его собственном суб-аккаунте.

Таблицы в `data/shop.db`:

- `di_subusers(user_id, pool, subuser_id, login, password, paid_gb, provisioned_gb)`
- `di_settings(user_id, pool, settings_json)` — гео, режим, TTL, формат, количество.

`paid_gb` — сколько гигабайт покупатель реально оплатил (дробное число),
`provisioned_gb` — сколько целых GB уже залито поставщику. API принимает только
**целое** число гигабайт (`POST /sub-user/balance/add`, `traffic: int`), поэтому
заливается `max(1, ceil(paid_gb))`: правило «минимума быть не должно» соблюдено —
можно купить 0.05 GB, суб-аккаунт получит 1 GB, разницу магазин дарит.
Остаток у покупателя считается как `paid_gb − balance_used`, где `balance_used`
берётся из `GET /sub-user/balance/get` (байты, делим на 2^30).

### Выдача прокси

Строки собираются локально — у поставщика нет ручки «выдай N прокси».
Гейт: `gw.dataimpulse.com:823` (HTTP/HTTPS CONNECT), таргетинг — в логине после
двойного подчёркивания: `login__cr.us;sessid.ab12cd34;sessttl.600`.

- **каждая строка получает свой `sessid`** — список никогда не состоит из N
  одинаковых строк (правило владельца от 2026-09-14);
- режим «Ротация» — короткий `sessttl` (`DI_ROTATING_TTL`, 60 с), IP меняется
  каждую минуту;
- режим «Фикс. IP» — `sessttl` из меню (5 мин … 2 ч).

Хост в выдаче подменяется на **свой релей** `31.77.145.160:18081`
(systemd `di-proxy-relay.socket` + `.service` на srv2, `systemd-socket-proxyd`
→ `gw.dataimpulse.com:823`) — тот же приём, что был для maskify на 18080.
Поставщик покупателю не виден. Переопределяется `DI_RELAY_ENDPOINT`.

### Цены

У DataImpulse нет эндпоинта с прайсом пулов, **но фактическую ставку видно в
`GET /sub-user/balance/addition-history`**: каждая запись хранит `traffic_added`
(сколько GB залито) и `balance_charged` (сколько списано с баланса реселлера),
их отношение и есть реальная цена за GB для этого пула.

Поэтому себестоимость не вводится руками: после каждого пополнения трафика
`_di_calibrate_cost()` читает лог и пишет наблюдаемую ставку в
`di_cost_<pool>`; кнопка **🧪 Проверить DataImpulse** делает то же самое сразу
по всем пулам, у которых уже есть суб-аккаунты, и показывает закупку. Значение
остаётся редактируемым в **🛠 Админка → ⚙️ Курсы и наценка** на случай, если лог
ещё пуст.

Цена для покупателя = закупка × (1 + `proxy_markup_percent`/100). Наценка по
правилу владельца — **100 %**, покупатель платит ×2 от реальной закупки.

**Значений по умолчанию нет намеренно.** Пока по пулу не получена закупочная
цена, он показывается как «цена уточняется», кнопка пополнения заблокирована, и
`_di_topup_execute()` отказывает ещё раз перед списанием. Продавать по
придуманной цифре нельзя — 2026-09-20 именно так и случилось: заглушки
1.00/1.80/2.00/0.30 попали в настройки и бот показал покупателям 2.00/3.60/4.00/0.60
$ за GB, взятые из воздуха. Заглушки удалены из базы и из кода.

### Выключатель раздела

Настройка `proxy_section_enabled` (`1`/`0`) убирает всю категорию «🌐 Proxy»
из главного меню бота: кнопки нет, а старые кнопки в чатах отвечают «Раздел
прокси временно закрыт». Переключается одной кнопкой в
**🛠 Админка → 🛒 Товары в категориях → 🙈 Скрыть / 👁 Показать раздел Прокси**.
С 2026-09-20 раздел **выключен** — до получения реальных закупочных цен.

### Админка

- **🔑 Ключи API и оплаты** → `DataImpulse login`, `DataImpulse password`
  (хранятся зашифрованными), кнопка **🧪 Проверить DataImpulse** — показывает
  баланс реселлера, число суб-аккаунтов и закупочную цену по каждому пулу
  (заодно записывает её в настройки).
- **🛒 Товары в категориях → 🌐 Proxy** — теперь список пулов: можно скрыть пул
  от покупателей или дать ему своё название (таблица `service_overrides`,
  код = имя пула).

## Переменные окружения (необязательные)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DI_API_BASE` | `https://api.dataimpulse.com/reseller` | база API |
| `DI_GATEWAY_HOST` / `DI_GATEWAY_PORT` | `gw.dataimpulse.com` / `823` | гейт поставщика |
| `DI_RELAY_ENDPOINT` | `31.77.145.160:18081` | что видит покупатель; пусто — отдавать гейт напрямую |
| `DI_ROTATING_TTL` | `60` | TTL сессии в режиме ротации, сек |

## Деплой

```
python project/_ops/srv_put_b64.py srv2 project/asf-dataimpulse/app/<file> /opt/asf/_stage_di/<file>
python project/_ops/srv_run.py srv2 "bash /opt/asf/deploy_di.sh"
```

`deploy_di.sh` делает бэкап в `/opt/asf/backups/<stamp>/`, байт-компилирует
staging, ставит файлы, перезапускает `asf`, проверяет `is-active` +
`http://127.0.0.1:8080/health` = 200 + отсутствие свежего `Traceback`, и при
неудаче сам откатывает бэкап.

`set_di_secret.py <di_login|di_password> <value>` — записать креды в
зашифрованные настройки, не вводя их в чат.

## Что осталось сделать

Нужен **login (e-mail) из раздела API Management** в дашборде DataImpulse —
пароль уже прописан. Без него `POST /user/token/get` отвечает
`422 The login must be a valid email address`, и все вызовы к поставщику падают
с «Прокси-сервис не настроен». После ввода логина в админке разделы оживают.
